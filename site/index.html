↑ the same words, as a panel shows them — 1 bit per pixel

Correct Arabic on LED dot-matrix panels.

Arabic letters change shape depending on their neighbours. Ordinary LED sign controllers store one fixed picture per character, so they cannot. This does the shaping in the phone's browser and sends the panel nothing but pixels.

Try it

32 × 8 pixels
Why this is hard

One letter, four shapes

Every Arabic letter takes a different form depending on what it joins to. The letter ع is written four ways, and choosing between them means looking at the neighbours.

ع
Isolated
عـ
Initial
ـعـ
Medial
ـع
Final

Some pairs must fuse outright: ل + ا = لا. Mandatory, not decorative.

A controller that stores one picture per character code has no way to ask what comes next. The limitation is architectural — it is not fixed by better fonts or more pixels, which is why it persists in products people buy today.
How it works

The browser does the hard part

Your phone already contains a complete Arabic layout engine — the one it uses for everything else. The page borrows it, then hands the microcontroller a finished image. Numbered because the order is load-bearing: each stage depends on the one before it.

01

Shape

Canvas draws the text, and the platform's own engine picks the contextual forms and ligatures.

02

Rasterise at 4×

Drawn oversized, so stroke shape survives as grey coverage rather than being lost.

03

Downsample

A box filter written in JavaScript, so every device computes identical coverage.

04

Threshold

Grey becomes lit or unlit. The cutoff is a control, because the right value differs by font and size.

05

Pack

Eight pixels per byte, row-major. Bit 7 of byte 0 is the top-left pixel.

06

The panel just displays it

No font, no shaping tables, no text logic on the device. It receives pixels and lights them.

Because the microcontroller holds no font, changing typeface or size costs nothing on the device — and any microcontroller can implement the receiver from the published frame format alone.

Anywhere a message changes often enough that reprinting it is a nuisance, and the audience reads Arabic.

Install and run

From nothing to Arabic on a panel

About thirty minutes if the parts are on the desk. You need an ESP32, a panel, five wires and a USB data cable — charge-only cables are the classic time sink.

  1. Wire the panel

    Five wires for a MAX7219: VIN→VCC, GND→GND, GPIO13→DIN, GPIO14→CLK, GPIO27→CS. Use 5 V, not 3.3 V — at 3.3 V the LEDs are dim and the driver's logic thresholds stop matching, which gives flicker rather than an honest failure.

    Do not use GPIO12. It is a strapping pin the ESP32 reads at boot to choose its flash voltage. A wire holding it high stops the board booting entirely, and nothing about the symptom points at your wiring.

  2. Install ESP-IDF

    Espressif's SDK. The --recursive flag matters: without it you get an incomplete download and a confusing build failure.

    git clone -b v5.3.2 --recursive https://github.com/espressif/esp-idf.git ~/esp/esp-idf
cd ~/esp/esp-idf && ./install.sh esp32
. ./export.sh          # needed in every new terminal

  3. Choose your panel and flash

    The panel type is a build-time setting. Everything above the driver is identical for all four.

    git clone https://github.com/mulhamfetna/arabic-led-text-pipeline
cd arabic-led-text-pipeline/firmware

idf.py menuconfig      # Arabic LED text pipeline → Display type
idf.py -p /dev/ttyUSB0 flash monitor

    You never press a button on the board — the USB-serial chip resets it into its bootloader automatically.

  4. Find the pixel orientation

    Generic MAX7219 modules wire their driver chip to the LED grid differently, and it cannot be detected in software — the chip has no readback line. So the firmware lights one corner at a time and logs which corner it intends:

    corner 1/4: logical TOP-LEFT      (x=0 y=0)
corner 2/4: logical TOP-RIGHT     (x=7 y=0)
corner 3/4: logical BOTTOM-RIGHT  (x=7 y=7)
corner 4/4: logical BOTTOM-LEFT   (x=0 y=7)

    Write down where each dot actually appears. Four observations determine the answer exactly — set the index in menuconfig and reflash. No guessing.

  5. Check it with Latin first

    A self-test scrolls HELLO WORLD at boot. This proves wiring, transport, geometry and packing using text whose correct appearance needs no interpretation. If English does not render correctly, Arabic never will — so fix that before going further.

  6. Connect a phone and type

    The board advertises a WiFi network called ARABIC-LED. Join it and open http://192.168.4.1/. No router, no internet, no app, no account.

    Type Arabic, watch the preview, press send. The preview is pixel-exact — it is drawn from the same bytes the panel receives.

Using it day to day

Six controls, and one of them needs explaining.

ControlWhat it does
النص — TextArabic, Latin, or both. Shaping happens in your phone's own text engine.
ثابت / متحركStatic fits the message to the panel; scrolling sends the whole phrase and moves it.
اتجاه الحركةArabic travels rightward, Latin leftward. Arabic's first letter is at the right end of the visual string, so it must move right to be revealed in reading order.
سرعة الحركةMilliseconds per pixel step. 60 ms reads comfortably.
حجم الخطText height in pixels.
سماكة الخطThe threshold where a grey anti-aliased pixel becomes lit. Lower gives fatter strokes. At 8 pixels tall this is the difference between a letter that reads and a blob — which is why it is a control and not a constant.

Questions

Frequently asked

Why do LED signs show Arabic letters disconnected?

Because conventional controllers store one fixed bitmap per character code. Arabic letters take up to four shapes depending on their neighbours — isolated, initial, medial, final — so picking the right one means looking at surrounding letters. A per-character lookup has no mechanism to do that.

The limitation is architectural. Better fonts and more pixels do not fix it, which is why it persists in products sold today.

Can an ESP32 really display Arabic correctly?

Yes — if the shaping happens off the device. The ESP32 serves a page from its own flash; the phone browser's text engine shapes the Arabic on a canvas, converts it to 1-bit pixels, and posts a packed framebuffer. The microcontroller stores no font and runs no text logic, so it needs neither HarfBuzz nor shaping tables.

Does it need internet, a router, or an app?

None of them. The board runs its own WiFi access point and DHCP server and serves the control page from flash at 192.168.4.1. A phone joins it directly. This matters for a sign in a shop or a mosque, where there may be no network at all.

What does it cost to build?

An ESP32 development board and an 8×8 MAX7219 module are the cheapest entry — a few dollars each at the time of writing. A P10 panel costs more but covers far more area. The firmware, documentation and protocol are free under AGPL-3.0.

Can I use it with my own controller or software?

Yes. The wire protocol is documented so that any microcontroller can implement a receiver from the specification alone, without reading this project's source. That is a stated design goal rather than a courtesy.

Is Arabic legible on an 8-pixel-tall panel?

This is the hardest open problem here, and worth being honest about. A survey found no published work on Arabic glyph design at 8–16 pixel heights — Latin has decades of bitmap-font craft, Arabic at that size is largely uncharted.

Whether readable Arabic that small needs purpose-designed letterforms, rather than reduction of existing typefaces, is genuinely unknown. Taller panels are easier.

How is this different from LVGL or u8g2?

LVGL already does Arabic shaping and bidi on microcontrollers — that is not the gap, and it is credited. But LVGL targets anti-aliased TFT screens, not 1-bit panels at 8–16 pixels.

u8g2 drives MAX7219 and ships Persian fonts, but its maintainer declined contextual shaping in 2018 on the grounds that the tables would be too large. Disconnected-letter reports have stayed open there from 2018 to 2024.

The gap this fills is narrow and specific: a Unicode-correct Arabic pipeline for 1-bit LED matrices.

Can it show colour?

On WS2812B addressable strips, yes — the wire format carries a 24-bit RGB mode, and the firmware estimates supply current and scales frames down to stay inside a configured budget. MAX7219 and P10 panels are monochrome; a colour frame sent to them is reduced by luma.

What comes next

Roadmap

Stated as intentions, not achievements. Anything already working is in the hardware table above; everything here is planned.

In progress

Arabic legibility below 16 pixels

Determining whether readable Arabic at 8px needs purpose-designed letterforms. The open research question, and the one that would most improve the result.

Planned

Hardware verification of P10, WS2812B and 74HC595

Three of the four drivers build but have never driven a panel. Each needs the same corner-probe bring-up the MAX7219 went through.

Planned

Message playlists and scheduling

Several messages cycling unattended, so the sign keeps working after the phone walks away.

Planned

Embedded webfont for cross-device consistency

Phones and laptops do not ship the same fonts, so identical text can render differently. Shipping a subset font would make output deterministic everywhere.

Planned

Freezing the wire protocol

Version 2 works but framing is not final — resynchronisation after a desync still leans on the CRC to reject false starts.

Considering

Larger panels and parallel scan chains

Beyond about 32 rows a scanned matrix is dim, because each row is lit a smaller fraction of the time. Splitting the panel into halves scanned in parallel is the real remedy.

Considering

Other right-to-left and complex scripts

The architecture is not Arabic-specific — the browser shapes whatever it can. Persian, Urdu and Hebrew are plausible without firmware changes.

Contributions are welcome, and so are reports from anyone who actually builds one — particularly on panels nobody here has tested.

Where it stands

What is not finished

Arabic shaping on microcontrollers is not new — LVGL does it, and standalone Arduino reshapers exist. What is missing is a Unicode-correct pipeline for 1-bit LED matrices at 8–16 pixels, which is the gap this fills.

Open questions, stated plainly: no published work was found on Arabic glyph design at these pixel heights, so whether readable Arabic that small needs purpose-designed letterforms is genuinely unknown. Output also varies slightly between devices, because phones and laptops do not ship the same fonts. Two of the four drivers have never been run on hardware.
